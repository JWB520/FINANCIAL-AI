# 研报核查与质量评估平台 · 桌面端

> 一句话：选一份研报 → 软件建好一个项目文件夹 → 在项目里做**勘误 / 评估 / 人工复核**三件事。

这是一个**桌面应用**：Electron 外壳（负责系统文件对话框与本地项目文件夹）+ React 前端（负责界面）。
之所以必须是桌面端，而不是纯网页：**要弹出系统原生的"选择文件 / 选择文件夹"窗口，并把真实路径存进项目配置**——
浏览器出于安全永远拿不到本地真实路径。

---

## 1. 怎么跑

> **工程根目录 = 仓库根目录**：`package.json`、`vite.config.ts`、`src/` 与这份 README 都在同一层，
> 没有 `frontend/` 子目录（本仓库就是前端工程本身）。

```bash
npm install          # 镜像配置在仓库自带的 .npmrc 里，不需要自己配
npm run desktop      # 一条命令：起前端服务 → 就绪后自动打开应用窗口
```

`npm run desktop` 做三件事（见 `scripts/start-desktop.cjs`）：起前端开发服务 → 等它就绪 → 拉起桌面窗口。
关掉窗口时它会顺手把前端服务也收掉。

| 命令 | 作用 |
| --- | --- |
| `npm run desktop` | ★ 正常使用：以桌面应用方式启动 |
| `npm run dev` | 只起网页版（浏览器里能看界面，但**无法选本地文件**——新建项目会给出提示） |
| `npm run build` | 类型检查 + 生产构建（产物 `dist/`，桌面端加载它） |
| `npm run verify` | 全部自检 112 项：落盘 36 + 假后端行为 17 + 核心逻辑 20 + 主线切换器 18 + 图表 9 + 页面渲染 12 |

> **首次安装要下载 Electron 二进制（约 100MB）**：仓库根目录的 `.npmrc` 已把 npm 包与 Electron 二进制
> 都指向国内镜像（npmmirror），所以换台电脑 clone 下来也能一次装通。
> 如果仍然报 `Downloading Electron binary... TypeError: fetch failed`，说明镜像没生效，
> 用环境变量再兜一次（npm 12 起不再把 `.npmrc` 里的自定义键透传给安装脚本）：
>
> ```powershell
> $env:ELECTRON_MIRROR='https://npmmirror.com/mirrors/electron/'; npm install
> ```

## 2. 项目存在哪、长什么样

工作区固定为 **`<文档>/RQC 项目库`**，一个项目 = 一个文件夹：

```
<文档>/RQC 项目库/
├── 中瓷电子 2026 年半年报点评/
│   ├── project.json      ← 配置文件：研报路径、知识库路径、创建时间、id
│   └── data/             ← 核查结果与导出文件；data/tasks/ 里是每次发送的任务参数留档
└── 源杰科技点评/
    ├── project.json
    └── data/
```

`project.json` 的实际内容（用户可以直接打开改，也可以在资源管理器里看到全部东西）：

```json
{
  "schema_version": 1,
  "id": "prj-20260926-a1b2",
  "name": "中瓷电子 2026 年半年报点评",
  "report_path": "D:\\研报\\中瓷电子2026半年报.pdf",
  "knowledge_dir": "D:\\知识库\\研究所规范",
  "dir": "C:\\Users\\<你>\\Documents\\RQC 项目库\\中瓷电子 2026 年半年报点评",
  "created_at": "2026-09-26T10:00:00.000Z",
  "updated_at": "2026-09-26T10:00:00.000Z"
}
```

落盘规则（都有测试覆盖，见第 6 节）：
- 项目名里的 Windows 非法字符（`\ / : * ? " < > |`）会被清洗；
- **重名自动加后缀**（`项目名-2`、`项目名-3`），绝不覆盖已有项目；
- 配置文件损坏的项目在导入列表里被跳过，不会连累其他项目；
- 文件夹改名不影响项目 id。

## 3. 界面只有三块（信息架构）

```
工作台 ──────────── 新建项目 / 导入已有项目（软件的全部入口）
   │
   ├─ 新建项目：选研报（系统文件窗口）→ 问是否关联知识库（系统文件夹窗口）→ 建项目 → 进项目界面
   └─ 导入已有项目：列出项目库（按时间倒序、可搜索）→ 选中 → 进项目界面

项目界面 ────────── 三个入口，就是软件的全部功能
   ├─ 勘误    → 先填任务单（选类型·可多选/全选，勾选后显示预估时长，每项可写分项备注
   │              → 用页码圈定范围 → 任务备注）→ 发送 → 进度页
   ├─ 评估    → 先填任务单（选维度 + 分项备注 → 选深度 快速/标准/深度 → 任务备注）→ 发送 → 进度页
   └─ 人工复核 → 直接进复核队列（AI 结论由人裁决：接受 / 驳回（需理由）/ 已核实 / 人工修改）

发送时做三件事：① 把本次参数留档到项目文件夹 `data/tasks/`；② 提交后端任务；③ 跳到进度页。
```

导航只有两组：**工作台**，以及支撑类的**经验学习 / 设置 / 帮助**。
勘误 / 评估 / 人工复核**不进左侧导航** —— 它们必须挂在某份研报上（结论不可能脱离它的项目去看），从项目界面进入。
进入任意一条主线后，**页面标题下方有一条「勘误 / 评估 / 人工复核」切换条**：三条主线一步直达，
切换时留在同一份研报上（从复核队列去勘误结果，不用再退回项目界面绕一圈）。
每条主线各有自己的落点：**勘误**＝结果总览（点其中的数字可直接下钻到那一条）；**人工复核**＝复核队列 → 复核裁决页（左原文 / 右结论，逐条裁决就发生在这里）。

| 路径 | 页面 | 谁能进来 |
| --- | --- | --- |
| `/` | 工作台 | 应用启动页 |
| `/projects/:projectId` | 项目界面（三个入口） | 新建或导入项目后 |
| `/reviews/:reportId/review` | 复核裁决（左原文 / 右结论，逐条裁决） | 复核队列、勘误结果的数字下钻；任意主线页顶部的切换条 |
| `/errata/:reportId/overview` | 勘误结果（风险分布、未覆盖、复核优先级） | 复核裁决页内跳转；任意主线页顶部的切换条 |
| `/errata/:projectId/annotate` | **勘误批注（左 PDF 原件 / 右批注卡）** —— 数字复算实验 | 项目界面 → 勘误 → 勾选类型后「发送」自动进入 |
| `/assessment/:reportId` | 评估明细（四个质量维度 + 参考分） | 项目界面 → 评估；任意主线页顶部的切换条 |
| `/reviews/:reportId/queue` | 复核队列（主张级） | 项目界面 → 人工复核；任意主线页顶部的切换条 |
| `/tasks/:taskId/run` | 核查执行进度 | 复核裁决页内跳转 |
| `/tasks/:taskId/audit` | 任务审计日志（模型/工具调用、耗时、token、追踪号） | 进度页 →「审计日志」 |
| `/learning` | 经验学习（案例 → 候选 → 审核发布 → 回滚 → 删除） | 导航 |
| `/settings` | 设置（工作区与数据 / 模型与推理 / 核查判据 / 知识库检索 / 界面偏好，**全部可改可存**） | 导航 |
| `/help` | 帮助（怎么用、概念解释、桌面端流程） | 导航 |

> 设置与经验学习都是**可写**的：设置存 `settings.json`（改完立即生效，不用重启）；
> 经验学习支持删除（候选任何状态都能删，已审核过的必须填理由；删\"生效中\"的规则版本会自动切回上一个历史版本；删除都会写审计）。

## 5. 和后端怎么接

> **后端同学请看 [`BACKEND.md`](./BACKEND.md)** —— 那份是写给你的：三十秒看懂现状、先做哪七条接口、
> 哪些字段和语义不能错、怎么五分钟把前端接上你的服务。

后端还没做时，业务数据走 `src/api/mock/`（假数据），字段与将来真实接口完全一致。
接后端时：`.env.local` 里 `VITE_USE_MOCK=false` 即可，**业务代码一行都不用改**。
接口清单、字段契约、联调排查顺序见 **`src/api/README.md`**。

> 项目文件夹（project.json）**不走后端** —— 它是本地工作区的组织方式。
> 唯一需要后端配合的是 `POST /reports/ensure`：打开项目时把"本地研报路径"与"后端报告实体"对上（幂等）。

## 5.5 勘误 / 评估的"可选项"清单在哪、怎么改

发起任务时那些勾选项**不是写死在页面里的**，集中在两个文件：

| 文件 | 内容 |
| --- | --- |
| `src/features/task-request/errataCatalog.ts` | 勘误类型：**6 组 26 项**（数据与计算 / 事实与出处 / 逻辑与一致性 / 表述与合规 / 估值与预测 / 格式与呈现），每项带一句说明 + 单项预估耗时；`estimateErrataMinutes()` 按勾选项与页码范围算总时长 |
| `src/features/task-request/assessmentCatalog.ts` | 评估维度：**6 组 17 项**（论证质量 / 数据与证据 / 风险与合规 / 同业一致 / 写作呈现 / 估值合理性）+ 三档深度（快速 ×0.4、标准 ×1、深度 ×2.5）；`estimateAssessmentMinutes()` 算总时长 |

> **26 项里已真正实现的只有 1 项：「数字复算」（`calc_number`）** ——
> 见 `src/pages/errata/ErrataAnnotatePage.tsx`（勘误批注页）与后端
> `backend/docs/勘误实验_数字复算.md`。勾了其他项时页面会写明"本次未实现"，不会假装查过。

改清单时的两条纪律（文件头注释里也写了）：
1. **`code` 上线后不要改** —— 任务请求与审计日志里存的是 code，改了历史记录就对不上；
2. 想清楚它是"查错"还是"评价"：查错归勘误，评价归评估（这是两条主线的分工）。

## 6. 自检（不需要点界面、不需要后端）

```bash
npm run verify          # 全部 112 项：落盘 36 + 假后端行为 17 + 核心逻辑 20 + 主线切换器 18 + 图表 9 + 渲染 12
npm run verify:store    # 项目落盘与配置 36 项：建/重名/非法字符/排序/PDF 页数/任务留档/配置读写与默认值合并
npm run verify:mock     # 假后端行为 17 项：删除、该拦的拦住（驳回必须填理由）、删掉被依赖的对象后自动兜底
npm run verify:core     # 核心逻辑 20 项：结论区间与原文逐字一致（高亮不错位）、计数自洽、覆盖率口径…
npm run verify:nav      # 主线切换器 18 项：路径→主线高亮、三个入口页在 router 里真实存在、三档渲染与选中态
npm run verify:charts   # 图表 9 项：在 Node 里无头渲染一张雷达图，证明"按需注册"没漏注册
npm run verify:render   # 页面能否渲染出 HTML（不白屏），12 项
npm run typecheck       # 类型检查（src 与 scripts 都检查，见 tsconfig.json 的 include）
```

> **为什么图表要单独验一项**：`echarts` 改成按需注册后体积从 1MB 降到 467KB，
> 但代价是**少注册一个组件时 echarts 不报错、只是安静地画不出来**——
> 类型检查、构建、页面渲染冒烟一个都发现不了。`verify:charts` 把"画得出来"断言住
> （已做反向验证：故意删掉雷达图注册 → 该脚本 3 项红、exit 1）。

> **为什么主线切换器也要单独验一项**：\"现在在哪条主线上、点一下去哪\"这段逻辑错了是**安静的** ——
> 类型检查与构建都不报，用户只会觉得\"点了没反应\"或\"跳错了地方\"。`verify:nav` 断言路径→主线、
> 三个入口页在 `router.tsx` 里真实注册过、三档都渲染出来且当前那档是选中态
> （已做反向验证：把切换器从复核队列页里摘掉 → 最后一条断言红、exit 1）。

> **关于"PDF 页数"（避免过度承诺）**：页码范围选择器需要一个总页数，桌面端**不装 pdf 库、自己尽力读**：
> 明文对象和**压缩对象流**（现代 PDF 的普遍形态）都覆盖。一次性实测 11 份真实 PDF：
> 9 份读到且与 PyMuPDF 的结果完全一致，另外 2 份是超过 64MB 的大部头、**故意不读**（避免主进程吃内存）。
> 扫描件、加密 PDF、超大文件一律返回"空"，界面会显示"请按实际页数填写"，**不会显示一个猜出来的数字**。

界面交互（点按钮、弹系统对话框）需要在真实窗口里人工过一遍，桌面端启动后按第 3 节的三步走一遍即可。

## 7. 界面简洁化的四条硬规矩

| # | 规矩 | 反例 |
| --- | --- | --- |
| 1 | 页面顶部只有：标题 + 最多一行浅灰说明 + 右侧 1~2 个主操作 | 在标题下写两三句"本页能做什么" |
| 2 | 解释性文字不进界面：能一句话说清放 Tooltip，说不清进代码注释 | 卡片标题写"核算过程（可复算，能自己验算）" |
| 3 | 一页只留一行筛选（`.toolbar`），次要信息降为小字或折叠 | 两组复选框平铺 + 统计 Tag + 内联图例挤一行 |
| 4 | 导航只放常去的入口：详情页从列表/项目点进去 | 导航列出系统里所有能打开的页面 |

> 自查一句话：把任何一页截图给没用过的人看，他能在 3 秒内说出"这页要我干什么"吗？
## 8. 踩过的坑（改代码前先看这一节）

| 坑 | 现象 | 怎么绕 |
| --- | --- | --- |
| **JSX 属性里嵌英文双引号** | `title="...出现"没有判据""` → `tsc` 报 `Identifier expected`，页面直接编译不过 | 属性值里一律用中文引号「」，别用 `"` |
| **文件行尾不统一** | `ReadAllText().Replace()` 明明文本一样却替换不生效（有的文件 CRLF、有的 LF） | 替换前先 `-replace "`r`n", "`n"` 统一成 LF，再替换；或用"按行定位 + InsertRange" |
| **PowerShell 命令体积上限** | 含大段中文的长命令被截断，写出来的文件损坏 | 一个文件分 2~3 段 `WriteAllText` + `AppendAllText` |
| **改了主进程却不重启** | 页面调用新 IPC 报"不是函数"，但代码明明写对了 | `electron/*.cjs` 改动后必须重启应用（渲染进程的 HMR 管不到主进程） |
| **主进程改注释伤到代码行** | `node --check` 报 `Unexpected token '*'`，应用起不来 | 改 `.cjs` 后跑一次 `node --check electron/main.cjs`（比启动应用快得多） |
| **"没做" 被当成 "没问题"** | 未覆盖 / 未评估 / 待复核 被算成通过，用户以为查过了 | 三态严格区分：`uncovered` / `not_started` / `pending` 不许用 0 分或空数组代替 |
