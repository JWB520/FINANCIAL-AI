# 勘误实验 · 数字复算（研报勘误 26 项中的第 1 项）

> 实验目标：把勘误清单里的 **「数字复算」**（`calc_number`）真正做通一次——
> 选中一份 PDF → 新建项目 → 勾勘误项 → 开始勘误 → **左栏 PDF 原件，右栏是以批注形式给出的问题**。
> 其余 25 项本次不实现（页面上会明确写"其他 N 项本次未实现"）。

---

## 1. 这条链路做了什么（六步分工）

用户要的那句话，落到代码里是六步，**每一步的职责都不许越界**：

```
① 取页    规则：按页取文本（PDF 的块先按页拼回连续文本，否则一句话会被版面切成好几块）   infra/parsers/pdf_parser.py
                                                    ↓
② 提取    大模型：从这一页里找出"能用本页数字验证"的量，写成算式 + 原文声称值        agents/prompts/extract_numbers.v4.md
           （模型只做翻译，不许算数、不许引入本页没有的数字）                    agents/calculator_checker.py
                                                    ↓
③ 复算    本地复算器：真的把算式算出来（含逐步过程）                          infra/tools/calculator.py
           （ast 白名单解析，不 eval；拒绝函数调用/属性访问）
                                                    ↓
④ 批注    大模型：把"原文/复算值/偏差"整合成一条批注                          agents/prompts/write_annotation.v1.md
           （模型挂了就用模板拼，逻辑一模一样）                              agents/calculator_checker.py
                                                    ↓
⑤ 复核    大模型：**整篇只调一次**。把"算不平"的条目连同原文一起交给它，
           逐条判：原文有误 / 只是四舍五入 / 机器自己配错 / 判断不了            agents/prompts/verify_mismatches.v3.md
           （只有"确认原文有误"才作为问题呈现；机器配错的从结果里剔除但留档可查）  application/errata_lab_service.py
                                                    ↓
⑥ 定位    解析器：把批注的原文句子换成**页面上的矩形框**（取词级坐标，按行合并）     infra/parsers/pdf_parser.py
           （拿不到就留空不画框；前端按"占页面宽高的百分比"摆，缩放/高分屏都无关）   features/pdf-viewer/
```

**为什么非要拆成六步，而不是"直接问模型这个数对不对"**：
让模型算数，结论就不可复算、不可解释。拆开之后，核算过程是本地算的，
用户点开能看到 `(260-165)÷165×100=57.58` 每一步；评委问"这个结论怎么来的"，
答案是"三步都是本地算的，模型只负责把中文翻译成算式"。

**第 ⑤ 步（复核）解决的是另一个问题：本地复算"算不平"不等于"原文写错了"。**
实测最典型的一次：原文写「分项收入 20.11/13.04 亿元，占比 60.67%/39.33%」，
它的占比是对的（20.11÷(20.11+13.04)=60.66%）—— 但正确的分母 33.15 需要把两个分项**相加**才能得到，
原文里根本没写这个数；而抽取提示词硬性要求"算式里的数字必须在原文逐字出现"，
模型只好退而同页的"全年营收 28.78"当分母，算出 69.87% → 判成"不一致"。
**这类"机器自己配错"的条目如果直接摆给用户看，就是在冤枉原文。**
所以新增第 ⑤ 步：把"算不平"的条目**连同原文上下文**一次性交给模型确认，
确认是原文有误才呈现；判成"机器配错"的从结果里剔除（但连理由一起留在 `review_excluded` 里可查，
不做静默删除）；判"判断不了"的降为「待人工确认」并把理由写成备注。

### 核查单元为什么是"一页"，不是"一句话"

第一版是**一句一调用**，实测（34 句 / 3 页研报）：调 34 次、只产出 1 条。
问题不在模型，而在**信息被切碎了**——研报里 `研发费用 2.90 亿 ÷ 营收 26.48 亿 = 研发费用率 10.95%`
这三个数散在**三句**里，逐句喂谁都拼不出来。

改成**整页一次**后：调用次数从"句数"降到"页数"（35 → 5 次），产出从 1 条到 4 条；
在 25 页的真实研报上：34 次调用、69K tokens、14 秒，产出 14 条批注。

批注定位不受影响：模型返回的 `statement` 会在这一页文本里检索出字符区间（`checker._evidence`）。

## 2. 四道防线（这是这次实验最值钱的部分）

放开模型自由发挥时，它会**凭空造出假问题**。实测抓到的三种，每一类都会让用户失去信任：

| 模型的错法 | 实例（真实输出） | 现在怎么挡 |
| --- | --- | --- |
| 自己算个数当"原文声称值" | 原文明写 59.6%，它算出 31.51 当声称值 → 本地复算又得 31.51 → 判"一致"。**自己跟自己对账** | **本地硬校验**：声称值必须在原文逐字出现 |
| 拿两个不同口径的数相除 | 归母净利润 5.39 亿 ÷ 扣非 4.65 亿，去"复算"56% 的增速（56% 是 4.65 相对它自己的上年数） | 提示词反例 + **本地硬校验**（算式数字必须在原文里） |
| 把输入当输出 | 算式 `36.27-6.38`，声称值却写成 `36.27` | **本地硬校验**：声称值不得等于算式中的操作数 |

三道防线各司其职：

1. **提示词写反例**（`extract_numbers.v4.md`）：把"看着像能算、其实不能"的六种陷阱逐条列出来，
   并明确"返回空是正确且常见的结果，不要硬凑"。
2. **本地硬校验**（`calculator_checker.validate_item`）：凡是**可以客观判定**的（这个数原文里到底有没有写），
   一律在本地判，不赌模型听话。挡下的条目**记账**并写在页面上（"另有 N 条因…被挡下"）。
3. **跨句不轻下结论**：算式的输入全部来自同一句 → `scope=sentence`，允许报"有问题"；
   借用了同页其他语句的数字 → `scope=context`，**只报"对得上"，算不平的转成「待人工确认」**
   （把算式和两个数都摆出来，让人一眼判断是模型搞错了还是报告真写错了）。
4. **呈现前复核**（`verify_mismatches.v3.md` + `errata_lab_service.review_mismatches`）：
   凡是"算不平"的条目，**连同原文上下文一次性**（整篇只调一次模型，省 token）交给模型逐条判四档 ——
   `原文有误` / `只是四舍五入` / `机器自己配错` / `判断不了`。
   只有"原文有误"才呈现为问题；"机器配错"的从结果里剔除，但**连理由一起留在 `review_excluded`**（不做静默删除）；
   "判断不了"的降为「待人工确认」并把理由写成卡片上的**复核备注**。
   这一步同时治两类毛病：
   · 上面第 3 条挡不住的**跨句配错**（本文 §1 那个 20.11/28.78 就是它挡下的）；
   · 以及**把四舍五入当成不一致** —— 本地比对用相对容差（0.5%），对接近 0 的百分比过严
     （原文 `-1.0%`、复算 `-1.0457%`，差 0.046 个百分点，纯写法精度，本地会判成不一致），
     `consistent` 这一档按"原文写法的精度区间"把它捞回一致。

> 题外话：挡假问题的代价是漏报。当前口径是**宁可漏、不可误报**——
> 一条"说人家错了其实没错"的批注，比十条漏掉的问题更伤这个系统的信用。

## 4. 三条接口（新增，不动既有 60 条端点）

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| POST | `/api/v1/errata/run` | 跑一次勘误，返回批注列表 + 统计 + 模型留痕 |
| GET | `/api/v1/errata/pdf` | 本地 PDF 的字节流（页面左栏渲染原件用） |
| GET | `/api/v1/errata/status` | 模型是否接入 / 已实现的勘误项 / 提示词版本 |

为什么 PDF 要过一道后端：页面在 `http://localhost:5173`，浏览器与 Electron 都**不允许网页直接读 `file://`**。
让后端把字节流出来，前端拿到的就是同源的 `/api/v1/errata/pdf?path=...`，也顺带让"看的是不是同一份文件"有据可查。

## 5. 实测结果（真实研报，可复现）

样本：`中瓷电子（003031.SZ）投资价值分析报告(6).pdf`（**25 页**，在仓库根目录）

| 环节 | 实测数字 |
| --- | --- |
| PDF 解析 | 25 页；按页拼回连续文本后，含数字的句子 **281 句** |
| 勘误产出 | **11 条批注**（有问题 0 / 复算一致 11 / 待人工确认 0） |
| **第⑤步复核** | 进入 **10 条**「算不平」→ 确认原文有误 **0** / 只是四舍五入 **3** / 机器配错已排除 **7** / 判断不了 **0** |
| 模型开销 | **36 次调用、约 78K tokens、耗时 15.6 秒**（并发 4；其中**复核只占 1 次调用**） |
| 被本地校验挡下 | 8 条（"自算自对"的比对，不计入结论） |
| **版面定位** | 留在结果里的批注**每条都能换回行框**（实测：第 7 页 2 条 → 各 2 个行框，框高约 15 点 ≈ 页高的 1.8%）；匹配不上就退回数字、再不行留空 |

> 抽取那一步有随机性（temperature 0.2），**逐次条数会浮动**，上表是某一次的实测；
> 但"复核四档"的分布很稳定，而且**每一条被排除的理由都可查**（见下方 `review_excluded`）。

抓到的真实问题（节选）：

| 页面 | 原文 | 复算 | 复核判定（这才是最终呈现给用户的） |
| --- | --- | --- | --- |
| 第 1 页 | 「电子陶瓷、第三代半导体收入分别为 20.11/13.04 亿元，占比 60.67%/39.33%」 | 20.11/28.78×100 = 69.87% | ⚪ **机器配错，已排除**：60.67% 的分母是本组两分项之和 33.15（20.11+13.04），20.11/33.15≈60.66%，与原文一致；机器误用同页全年营收 28.78 当分母 |
| 第 7 页 | 「…由 2025 年 165 亿美元增长至 2026 年 260 亿美元、**两年增速均为 +60%**」 | (260-165)/165×100 = **57.58%** | 🟡 **待人工确认**：57.58% 与 60% 确实对不上，但原文"两年"二字使 165→260 究竟跨几年说不清、缺基期数 —— 留人看，**不下"原文有错"的结论** |
| 第 12 页 | 营业收入表 `26.76 26.48 …`／YoY `-1.0%` | (26.48-26.76)/26.76×100 = **-1.0457%** | 🟢 **一致**：差 0.046 个百分点，落在原文「-1.0%」的精度区间（±0.05）内，属四舍五入 |
| 第 18 页 | 「以归母收入…2027E 约 2.45 亿元计，板块价值约 **7—10 亿元**」 | 2.45×3 = 7.35 | 🟢 **一致**：7.35 落在原文给的区间内，取区间下限 7.0 对比属四舍五入 |
| 第 2 页 | 「股价 137.72 元对应 2026 年 **PE 60.2 倍**」 | 137.72/2.29 = **60.14** | 🟢 一致 |

> 第 12 页那条特别值得记：本地比对用**相对容差**（0.5%），对接近 0 的百分比过严，
> 会把这种正常四舍五入判成"不一致" —— 是第⑤步的 `consistent` 档把它捞回来的。

## 6. 已知限制（诚实列出）

1. **只实现了 26 项里的 1 项**（`calc_number`）；其余 25 项只接受勾选、不做处理，页面会写明"本次未实现"。
2. **规则模式覆盖率极低**（真实研报上命中 0 条）—— 它只认"由 A 增至 B，增长 C%"这类句式，
   且**只报一致不报不一致**（规则抽的算式是猜的，猜错就误报）。所以**不配 Key 时这个功能基本看不到东西**。
3. **表格只能"凑巧"命中**：PDF 表格抽成一行文本（`毛利率 36.41 36.86 37.13 37.02`），
   模型能从里面配出关系，但列头对不上，结论解释性弱于正文。
4. **PDF 版面标注是"行框"，不是逐字高亮**：右栏选中一张卡 → 左栏**那一行直接画出框**，
   并自动滚到视野中间（不必再自己满篇找）；点框也能反过来选中对应的卡片。框由
   "原文句子 → 词级坐标 → 按行合并"算出，因此：
   · 一条批注跨多行时会有多个框（角标标 `1/2`、`2/2`）；
   · 句子在 PDF 里匹配不上（表格、跨栏排版常见）时，退回用**原文数字**定位（`rect_match=number`）；
   · 两者都拿不到就**留空不画框**（宁可少画，也不把框画到别处），并在页面提示里如实报数；
   · 旋转页（`/Rotate`）暂不画框 —— 坐标换算没做，本项目研报不涉及。
5. **扫描件不支持**：没有文本层的 PDF 会明确报 `REPORT_PDF_PARSE_FAILED`。
6. **未接入既有任务流水线**：勘误不走 `POST /tasks`（后端五阶段编排还是骨架）。
   发送勘误任务时只做本地留档 + 直接进批注页；等任务编排做完，改回 `taskApi.submit()` 即可（代码里有注释）。


复核那一步的每条分支也都有断言钉着（`tests/test_errata_lab_model.py` 共 8 项）：假 provider 分别回
`report_error` / `consistent` / `tool_mispair` / `unclear`，四种情形分别断言"呈现为高风险 / 判为一致 /
从结果里消失且留档可查 / 降为待人工确认并带备注"；另有两项钉住"没有模型时复核整段跳过、判定一律不变"
与"复核输入必须带原文上下文"。

另外**本地校验这层单独有 4 项断言**（`test_validate_rejects_*`），钉住"模型编的数一律挡下、
真恒等式必须放行"——不然把校验写严一点就会把功能关掉，写松一点假问题就回来了。
